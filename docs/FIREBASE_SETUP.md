# إعداد Firebase لسيبويه

## المشروع والحسابات

1. أنشئ مشروع Firebase مستقل لسيبويه أو استخدم المشروع المخصص له. لا تستخدم مشروع تطبيق أثر أو بيانات طلبته تلقائيًا.
2. أضف Android app بمعرّف `com.sibawayh.academy`.
3. فعّل Authentication → Email/Password. رقم الهاتف في هذه النسخة بيان تواصل وليس تحقق SMS.
4. أنشئ قاعدة Firestore الافتراضية في Native/Standard mode على خطة Spark إذا كانت مناسبة لاحتياجك. لا تُفعّل test mode المفتوح للطلبة.
5. انشر ملف `firebase/firestore.rules` من Console أو بالـCLI: `firebase deploy --only firestore --project YOUR_PROJECT_ID`. لا تحتاج Cloud Functions لهذه الوظائف.

## تمرير إعدادات التطبيق

من إعدادات تطبيق Android في Firebase استخرج قيم FirebaseOptions (يمكن توليدها أيضًا عبر FlutterFire CLI). أضف القيم العامة التالية في GitHub → Settings → Secrets and variables → Actions → Variables:

- `FIREBASE_API_KEY`
- `FIREBASE_APP_ID` — Firebase Android app ID، وليس اسم الحزمة فقط.
- `FIREBASE_PROJECT_ID`
- `FIREBASE_MESSAGING_SENDER_ID`

ثم أعد تشغيل workflow `Sibawayh Flutter and Firebase`. الـworkflow يمررها بـ`--dart-define`. تهيئة Firebase صريحة في Dart، ولا تشترط هذه النسخة وضع service account أو ملف Google Services سري داخل المشروع. قيّد API keys حسب إعدادات المشروع ولا تعتبرها بديلًا عن Security Rules.

لا تُرسل كلمة مرور حساب Google أو مفتاح Service Account في المحادثة أو تضعهما داخل APK. إعدادات العميل العامة ليست صلاحية إدارة.

## تفعيل حساب المالك مرة واحدة

1. افتح APK المربوط بالمشروع وسجّل حسابك العادي.
2. من Firebase Authentication انسخ UID لهذا الحساب.
3. من Firestore Console أنشئ مستندًا في collection `roles` بمعرّف UID نفسه، وداخله `owner: true` كقيمة Boolean.
4. أعد تسجيل الدخول. تظهر أيقونة «إدارة المنصة» في الأعلى وفي حسابي.
5. من السوبر بانل اضبط رقم واتساب دوليًا بدون + أو مسافات، والصور والصفوف والأقسام، ثم أنشئ الكورس الدراسي الخاص بكل صف وأضف المحاضرات.

لا يمكن لطالب أو مالك إنشاء مستندات `roles` من التطبيق. حصر كتابة الصلاحيات خارج العميل يمنع الطالب من إعطاء نفسه دور المالك.

## البداية بالمحتوى والاشتراكات

- كورس دراسي لكل صف يضم كل أقسامه. التفعيل من شاشة الطالب في السوبر بانل ومدته 30 يومًا.
- «طور نفسك» كورس مستقل. التفعيل لا يُورث من الاشتراك الدراسي.
- التجديد يتطلب تأكيد الدفع من الإدارة. يوجد request ID يمنع تكرار نفس العملية عند إعادة إرسالها. وقت هاتف المالك يجب أن يكون صحيحًا عند التجديد؛ قواعد انتهاء الوصول نفسها تستخدم وقت خادم Firestore.
- الاختبارات تضاف مخفية، ثم تضاف الأسئلة ومفاتيحها، وبعدها تنشر. لا تعدّل اختبارًا أثناء حل الطلبة. تعديل الأسئلة يتطلب إخفاء الاختبار، ما يوقف التسليم إلى أن يُعاد النشر.
- الدرجة والإجابات النموذجية في مجموعات لا يكتبها الطالب، ولا يقرأ الدرجة قبل إتاحة النتائج. طالب لا يستطيع تعديل تسليم بعد تقديمه أو توقيت البداية أو مدة المحاولة.
- إعادة فتح محاولة من الإدارة تحذف المحاولة والدرجة السابقة بعد تأكيدك؛ صدّر/احتفظ بها خارج المنصة إذا احتجت أرشفة ثابتة قبل الإجراء.

## ما لم يتم إعداده تلقائيًا

لم يتم إنشاء مشروع Firebase أو نشر قواعد على حساب المستخدم أو منح حساب مالك فعليًا؛ يتطلب ذلك بيانات المشروع الصحيح. لا توجد مفاتيح خدمات في المستودع. لا يوجد تحقق Play Integrity/App Check مفروض بعد، ولا نظام منع إساءة الاستخدام متكامل؛ اختبارات Emulator تتحقق من قواعد الصلاحيات المحددة، وليست ضمانًا ضد كل إساءة استخدام أو استهلاك للحصص.

لا يُنصح بنشر بيانات بنكية أو حساسة في مشروع تجربة. صور المدرس وهوية سيبويه مخصصة للمشروع ولا يُعاد استخدامهما كعلامة تجارية عامة.
