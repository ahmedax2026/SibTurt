## حدود يجب عدم إخفائها

لا يمكن ضمان أن روابط YouTube/Drive تعمل داخل التطبيق فقط أو تبقى محمية بعد نسخها. لا يجوز إزالة وظائف YouTube المطلوبة أو تغطيتها بعلامة مائية. صورة داخل التطبيق قابلة للتغيير عن بعد، وأيقونة نظام الهاتف تحتاج إصدار APK جديد.

Firebase project config وحساب المالك ورقم WhatsApp غير متوفرين بعد. لا يوجد Firebase منشور أو تسجيل حقيقي مرتبط بمشروع المستخدم حتى يتم إعداد ذلك. لا تضع مفاتيح Admin SDK أو service account داخل التطبيق أو GitHub. Cloud Storage وCloud Functions يحتاجان Blaze؛ الأساس المجاني يستخدم Auth/Firestore مع حصصهما، ويمكن تخزين صور واجهة صغيرة أو روابط صور. توقيع روابط R2/Stream السرية يحتاج backend موثوقًا إضافيًا، ولا يوضع سر التوقيع في Flutter.

## دفعة Flutter/Firebase — ملفات مكتوبة وجارٍ التحقق

تمت كتابة مسار `student_mobile_app/lib/sibawayh/` (store/app/admin/player/quizzes)، وتغيير main إلى واجهة سيبويه مع الاحتفاظ بالدخول القديم في main_tutorloom.dart. أُضيفت قواعد Firestore واختبارات صلاحيات وworkflow مستقل لبناء Flutter APK. لم يُعلن نجاحها بعد؛ يجب فحص نتائج `Sibawayh Flutter and Firebase` وإصلاح أي أخطاء ثم تحديث هذه النقطة.

السوبر بانل المكتوب يشمل هوية وصور داخلية وروابط/اختيار صور صغيرة، الكورسات والمحاضرات وترتيب السحب والإخفاء، الطلبة والتجديد/الإلغاء/الإيقاف، أقسام وصفوف، وأسئلة اختيار/مقالي واختبارات وواجبات وتصحيح من حساب المالك وإتاحة النتائج. التصحيح المجاني يتم عند فتح ورقة الطالب من المالك: اختيار متعدد محسوب، ومقالي يدوي؛ لا يوجد Cloud Function مجاني لتصحيح لحظي عند تسليم الطالب.

لم تُنشأ موارد Firebase أو تُنشر قواعد على مشروع المستخدم؛ البناء بدون إعدادات Firebase يجب أن يعرض «معاينة قبل ربط Firebase» ولا يدعي وجود تسجيل عامل. مفاتيح Firebase العامة يمكن تمريرها عبر Repository Variables الأربع المذكورة في workflow، بعد تسجيل Android app بالمعرّف com.sibawayh.academy. حساب المالك يُمنح خارج التطبيق بوثيقة roles/UID فيها owner=true، ولا يسمح للعميل بكتابة roles.
